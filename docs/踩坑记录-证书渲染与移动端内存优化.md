## 一、背景

系统把防爆合格证 / CCC 证书 PDF 以 base64 形式存储，并在前台展示下载按钮。证书数量与体积逐步增长后，连续暴露了三个同类问题，根因都指向 **「base64 在错误的时机被放进内存 / DOM」**。

## 二、问题与结论

| # | 现象 | 根因 | 修复 |
|---|------|------|------|
| 1 | 上传证书后刷新页面，下载按钮消失 | 初始化竞态：`rebuildCertData` 未等 `loadCertsFromIDB` 完成就渲染；`loadCloudData` 在 `/api/data` 返回 404（静态托管不抛异常）时跳过 localStorage 兜底 | `loadCloudData` 始终用 `{内置, 导入}` 重建 `CERT_DATA`；`rebuildCertData` 改为 `async` 并 `await loadCertsFromIDB()` |
| 2 | 后台清空数据，内置 YBX3/YBX4 清不掉；导入其他系列前台不显示 | 内置 `CERT_DATA` 写死在代码里，旧逻辑 localStorage 为空时回退到默认值 | 引入 `cert_builtin_cleared` 标志 + 「恢复默认数据」按钮，始终重建 `CERT_DATA` |
| 3 | 上传部分证书后再上传报 `Invalid string length` | 下载按钮把证书 base64 直接写进 HTML `href` 属性，证书多/PDF 大时拼接的 HTML 字符串超长 | 下载按钮改为 `data-ref` 引用，点击时由 `window.__downloadCert()` 动态取 base64 触发下载 |
| 4 | 手机端打不开（桌面正常） | 启动 `loadCertsFromIDB()` 把所有证书 base64 **全部加载进内存**（`certMemCache`），移动端内存上限更低直接把标签页撑崩 | 改为**按需加载**：启动只 `getAllKeys()` 记录引用 key 集合；点击下载时才从 IndexedDB 取 base64 |

## 三、核心方案：base64 三层解耦

> 关键原则：**base64 不进 localStorage、不进 HTML、不进启动内存**，只在「点击下载」这一刻按需从 IndexedDB 读取。

1. **持久化**：证书 base64 存 IndexedDB（`CertFilesDB` / `certFiles`），记录在证书字段里只保留引用 key（格式 `系列名|序号|类型`，如 `YBX4系列|0|ex`）。
2. **DOM**：下载按钮用 `data-ref` 引用 key，绝不内嵌 base64；渲染时下钻判断 `hasCert()` 只查引用集合，不取 base64。
3. **内存**：`loadCertsFromIDB()` 启动只收集 key 到 `availableCertRefs`（Set）；`certMemCache` 仅在下载点击后临时填充单个证书，用完即留（可进一步优化为下载后清除）。

## 四、验证方式（Playwright 移动压测）

- 视口 390×844（iPhone 12 UA），注入 **60 个产品 / 约 360MB 证书 base64** 到 IndexedDB + localStorage；
- 重新加载：页面正常渲染（卡片、下载按钮齐全），**无崩溃、无报错**；
- 点击下载按钮：`window.__downloadCert` 从 IndexedDB 按需取回 base64，下载触发成功。

> 对比：旧代码在同样数据下会把 360MB 全载入 `certMemCache`，移动端必崩。
